# LeRobot Diffusion / PushT: измеренная проверка 19 октября 2026

## Результат

Завершён экспериментальный цикл RobotCI: скачать и проверить checkpoint,
исполнить обученную политику в CPU-симуляторе, сохранить эпизоды, повторить
baseline и обнаружить регрессию от реального изменения действий.

| Запуск | Успехи | Средняя максимальная награда | Шаги по seed 1000 / 1001 / 1002 | Gate против baseline |
| --- | ---: | ---: | --- | --- |
| Baseline, `action_scale=1` | 3/3 | 1.000000000000 | 161 / 212 / 128 | Эталон |
| Неизменённый повтор, `action_scale=1` | 3/3 | 1.000000000000 | 161 / 212 / 128 | `PASS`, exit 0 |
| Удержание позиции, `action_scale=0` | 0/3 | 0.085499310864 | 300 / 300 / 300 | `REGRESSION`, exit 4 |

Это девять фактически исполненных эпизодов на окончательном формате протокола.
Результаты не получены правкой итогового JSON или подстановкой награды.
Основные данные сохранены в
[каталоге доказательств](../../experiments/lerobot_pusht/evidence/2026-10-19/),
включая исходные траектории, результаты и отчёты сравнения.

Три заранее выбранных seed проверяют работоспособность интеграции и заданной
регрессионной проверки. Они не устанавливают общую успешность обученной модели,
качество другого checkpoint или пригодность для физического робота.

## Фиксированный протокол

- Окружение: `gym_pusht/PushT-v0`, наблюдение `pixels_agent_pos`.
- Вход изображения: RGB uint8 96×96, преобразование в float32 CHW и деление на 255.
- Двумерное состояние: фактическая позиция управляемой точки.
- Seed: **1000, 1001, 1002**, в одинаковом порядке во всех трёх группах.
- Перед каждым эпизодом сбрасываются Python/NumPy/Torch RNG, очередь политики и
  окружение с соответствующим seed.
- CPU, один Torch-поток, float32, `torch.use_deterministic_algorithms(True)`.
- Управление 10 Гц, не более 300 шагов на эпизод.
- **10** DDPM denoising steps; веса политики и её normalization buffers неизменны.

Проверочный профиль с 10 шагами диффузии отличается от исходной конфигурации
checkpoint, использующей полный scheduler. Опубликованная авторами оценка на
500 эпизодах здесь не воспроизводилась и не используется как результат RobotCI.

В candidate изменён только масштаб применения действия:

```text
applied_target = clip(observed_position + action_scale * (policy_target - observed_position), 0, 512)
```

При `action_scale=1` окружение получает предсказанную абсолютную цель.
При `action_scale=0` окружение получает текущую позицию точки. Инференс той же
модели продолжает выполняться, но её движение не применяется. Награда измеряется
самим PushT после каждого фактически переданного действия.

Для ухудшенного варианта максимальная награда по seed составила **0.0**, **0.0**
и **0.2564979325910711**. Последнее значение отражает перекрытие в исходном
положении, а не успешно выполненное перемещение: все эпизоды завершились по
лимиту 300 шагов без успеха.

## Повторяемость и точность

Неизменённый повтор сохранил все три успешных исхода и числа шагов. В каждой
паре полностью совпали действия модели, применённые действия, позиции,
хеши RGB-наблюдений и терминальные флаги.

Полные байты trajectory совпали для seed 1000. Для 1001 и 1002 обнаружено только
различие последних двоичных разрядов промежуточной награды: максимальное
абсолютное отклонение **4.440892098500626e-16**. Поэтому утверждение о побайтовой
идентичности всех трёх записей было бы неверным. Исходные записи сохранены без
округления и имеют собственные SHA-256.

Офлайн-верификатор проверяет каждый фактический SHA-256. Затем он требует
точного совпадения всей повторной траектории, кроме поля промежуточной награды,
для которого явно задан `abs_tol=1e-12`, `rel_tol=0`. Этот допуск относится
только к численному сравнению повторов и не меняет правила регрессионного gate.

Средняя максимальная и финальная награда baseline/repeat равны 1.0; поэтому
наблюдаемая погрешность промежуточных вычислений не влияет на вердикт `PASS`.
Время исполнения записано для диагностики: около **163.04**, **151.67** и
**255.47** секунды на соответствующие группы. Это не бенчмарк задержки CPU:
процессы выполнялись вместе с другими проверками, wall-clock время не участвует
в решении о регрессии.

## Проверка gate и файлов

Команды `robotci lerobot compare` запускались через установленный core CLI,
которому для чтения результатов не нужны Torch или LeRobot.

| Проверка | Полученный результат |

| Baseline против неизменённого повтора | `PASS`, код 0; JSON и Markdown сохранены |
| Baseline против удержания позиции | `REGRESSION`, код 4; JSON и Markdown сохранены |
| Падение доли успехов | 1.0 при допустимом 0.0 |
| Падение средней максимальной награды | 0.9145006891363097 при допустимом 0.05 |
| Исходные результаты и траектории после сравнения | SHA-256 всех 12 JSON файлов неизменны |

Результаты сравнения:
[неизменённый повтор](../../experiments/lerobot_pusht/evidence/2026-10-19/reports/unchanged.md),
[ухудшенный вариант](../../experiments/lerobot_pusht/evidence/2026-10-19/reports/degraded.md).
[Манифест](../../experiments/lerobot_pusht/evidence/2026-10-19/manifest.json)
содержит размеры и хеши сохранённых файлов, а также хеши исходных модулей
производителя в неизменённом `producer_files`. Хеш самостоятельного скрипта
проверки сохранён отдельно в `verification_files`. Веса размером 1.05 GB
не включены в Git.

Самостоятельная приёмка завершилась **PASS**: проверены все девять trajectory
файлов, непрерывность наблюдений, применение масштаба действий, согласованность
эпизодных метрик, повторяемость и оба ожидаемых gate. Сохранены переносимые
[acceptance.md](../../experiments/lerobot_pusht/evidence/2026-10-19/acceptance.md)
и [acceptance.json](../../experiments/lerobot_pusht/evidence/2026-10-19/acceptance.json).

В производном JSON приёмки изменены только три поля `runs.*.directory`:
абсолютные пути заменены на `baseline`, `unchanged` и `degraded` относительно
каталога evidence. Остальные поля отчёта сохранены; Markdown скопирован
побайтово. Источник и нормализация отмечены в `derived_reports` манифеста.
Все 12 исходных `result.json` и trajectory-файлов остались побайтово неизменными.
Манифест содержит размеры и SHA-256 всех 19 файлов evidence, кроме самого себя.

Метрики gate вычисляются заново из валидированных эпизодов. Неполный запуск,
невалидный JSON, различный полный protocol или baseline без единого успеха
получают `INFRA_ERROR`, код 3. Инфраструктурная ошибка не превращается в
неудачный эпизод робота. Пороговое равенство проходит проверку; сравнение
десятичных значений использует точные дроби.

Portable `compare` проверяет структуру результатов и формат хешей, но не читает
внешние trajectory-файлы и не удостоверяет личность производителя. Для проверки
самих сохранённых трасс предусмотрен отдельный
[verify_lerobot_pusht.py](../../scripts/verify_lerobot_pusht.py).

## Проверка кода и границы

Полный локальный Python suite с самостоятельным acceptance-верификатором:
**1475 passed**, без skips и исключённых тестов, за **46.77 секунды**. В него
вошли новые проверки загрузки checkpoint, CLI, контракта результатов, правил
gate, проверки сохранённых траекторий и изоляции optional runtime.
Ruff всего репозитория и `git diff --check` прошли. Регрессионные тесты отдельно
проверяют пропавшие обязательные входы Diffusion/SmolVLA, незавершённые HTTP
ответы, несовместимые протоколы, нечисловые значения, невозможность перезаписать
выходы и ошибки записи отчётов.

Собранный wheel проверен в отдельном чистом core-окружении вне checkout:
все 55 Python-файлов пакета совпали с исходниками побайтово. Установленная
команда `inspect` вернула `VALID`/0, сравнения сохранённых результатов —
`PASS`/0 и `REGRESSION`/4. Попытка `run` с настоящим закреплённым checkpoint
в этом окружении без ML-зависимостей вернула `INFRA_ERROR`/3, пустой список
эпизодов и не создала trajectory-файлов. Это подтверждает границу optional
runtime у установленного пакета. Сам wheel не включён в evidence или Git.

Предварительные экспериментальные прогоны с ранним, более коротким fingerprint
не используются как окончательная проверка контракта. После фиксации всех 17
версий и архитектуры проведены новые baseline/repeat/degraded, описанные выше.

Этот этап не добавляет исполнение ACT или SmolVLA, обучение, управление
SO-101/Panda/Unitree, аппаратные подключения или воспроизведение PushT в
существующем Nav2 3D viewer. Для ACT/SmolVLA сохраняется только metadata preflight;
для моделей роботов — отдельный static-reference импорт. Критерии внешних
пилотов M8 и реестр команд этим экспериментом не изменяются.
